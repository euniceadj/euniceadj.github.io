Eunice — Project Lead

I served as project lead for the E-MAGINE Healthcare Network Redesign, responsible for the overall security architecture, ACL framework, ASA firewall configuration at both Main and Orlando sites, compliance mapping to HIPAA and three state-level data privacy laws, and the APA technical report.

Beyond my core responsibilities, I supported the team through troubleshooting across all sites; resolving EIGRP route advertisement issues, diagnosing DHCP failures, identifying a Packet Tracer IOS limitation affecting the Orlando router, and configuring the VPN simulation path. I also assisted with the physical equipment lab, producing the Week 4 demo submission document.

A key design decision I made independently was adding and configuring the DMZ as a logical ASA-enforced zone on the Main firewall, isolating public-facing services from the internal network; a control required under HIPAA's transmission security standards.

The case

E-MAGINE is a multi-site healthcare organisation handling electronic Protected Health Information across three original locations: a Main site in Virginia, an Orlando branch, and a centralised Data Center, with a Chicago office added during the project.

When the redesign began, the network was not in a state appropriate for an organisation handling ePHI. The Data Center was running hubs instead of managed switches, broadcasting all traffic with no ability to control who could see it. Orlando had a consumer-grade wireless router with no enterprise security features and a passive network sniffer permanently connected to the environment, giving uncontrolled visibility into traffic in transit. Across all sites, IP addressing was unstructured and inconsistent. There was no firewall segmentation, no encrypted remote access, no centralised audit logging, and no access controls that met HIPAA standards. The Data Center also had a direct internet path that bypassed perimeter inspection entirely.

The goal of the redesign was to bring all four sites behind a unified, compliant network. This meant replacing non-compliant equipment, segmenting traffic by function and sensitivity, enforcing encrypted access, and building audit and control mechanisms sufficient to meet HIPAA, NIST, and three state-level data privacy frameworks.

02 — Design pillars
Key components

Eight engineering controls each tied to a compliance requirement

EIGRP Dynamic Routing

DUAL algorithm automatically reroutes on WAN link failure. Neighbour adjacencies verified on all routers including Chicago-R1, Main-R1, Orlando-Router0, and DataCenter-R1.

AS 100 · auto failover

VLAN Segmentation

Orlando uses VLANs 10–50 for departmental isolation. DC uses VLANs 10 (Management), 20 (Infrastructure), and 30 (ePHI), each on separate subnets limiting blast radius.

VLANs 10–50 · ePHI isolation

ASA Firewalls & ACLs

ASA 5506-X at Main and Orlando-ASA1 enforce zone-based policy. Extended ACLs on all routers with default-deny posture. Stateful inspection on ICMP and HTTP.

ASA 5506-X · default deny

DMZ

Isolated zone off the Main ASA separating public-facing services from the internal LAN. Prevents direct inbound access from the internet to internal segments.

off Main-ASA · isolated

Remote Access VPN

Simulated via HomeRouter-PT VirtualNetwork. The Remote User connects through a virtual router to the Main ASA, representing an encrypted remote access tunnel into the network.

VirtualNetwork · Main ASA

TACACS+ Centralised AAA

TACACS+ and AAA/RADIUS servers in DC VLAN 10 (172.16.10.2). Syslog server at 172.16.10.3 for audit logging. SSH v2 on all routers, Telnet disabled.

172.16.10.2 · SSH v2

Port Security

Sticky MAC addresses on all access switches (2960-24TT at Chicago/Main, 2960 at Orlando) with violation shutdown. Unauthorised devices blocked at port level.

sticky MAC · shutdown

Spine-Leaf DC Fabric

Two 3650-24PS spine switches and two 3650-24PS leaf switches in the DC. VLANs 10, 20, and 30 servers verified reachable from leaf SVIs. Non-blocking east-west traffic.

3650-24PS · non-blocking

05 — Efficiency
Network efficiency

How the design optimises performance across all four sites

VLAN Segmentation

Segmenting the network into VLANs reduces congestion and creates better performance and security. Broadcast domains are contained per department, reducing unnecessary traffic across the WAN.

Logical IP Addressing

Subnets are organised and non-overlapping across all sites. This structured IP scheme improves routing efficiency and makes troubleshooting straightforward. Each subnet maps to a specific site and function.

EIGRP Path Selection

EIGRP allows routers to choose the most efficient path for data using composite metrics including bandwidth and delay. Routes are shared automatically between routers without manual static configuration.

06 — Scalability
Built to grow

How the design accommodates future expansion without redesign

Spine-Leaf DC

Spine-leaf architecture supports horizontal scaling without redesigning the core. Additional leaf switches can be added as server demand grows.

horizontal scale

EIGRP Auto-Discovery

EIGRP automatically discovers and advertises new networks as sites are added to the WAN, with no manual route configuration required for new locations.

dynamic · auto-advertise

VLAN Flexibility

VLAN structure allows new departments to be added by assigning ports without reconfiguring routers. Simply tag the port to the appropriate VLAN.

port-based · no reconfiguration

Unused WAN Ports

Serial WAN links include unused ports on routers to accommodate future site connections. Adding a fifth site requires only cabling and EIGRP configuration.

expansion-ready

Modular ISR Routers

Modular ISR 4321 routers support additional interface cards as traffic demands grow. Bandwidth can be increased without replacing the entire router.

ISR 4321 · modular
07 — Resilience
Network resilience

Redundancy and fault tolerance built into every layer

EIGRP DUAL Algorithm

Automatically reroutes traffic when a WAN link fails using feasible successors. No manual intervention needed and no downtime for users.

Dual Serial WAN Connections

Dual serial connections between main routers provide redundant paths across the WAN. A single link failure does not isolate any site.

Spine-Leaf DC Redundancy

Spine-leaf topology in the Data Center provides redundant paths between servers and the core. Each leaf connects to both spine switches.

Independent ASA Boundaries

ASA firewalls at Main and Orlando provide independent security boundaries. If one site is compromised, the other continues operating with its own perimeter intact.

VLAN Blast Radius Containment

VLAN segmentation limits the blast radius of any single device or link failure. A problem in one VLAN cannot propagate to other segments without passing ACL inspection.

09 — Risk Analysis
Threats & mitigations

Four risks identified with impact and likelihood ratings from the project

Risk Impact Likelihood Mitigation
Unauthorized ePHI Access Critical Low Access to ePHI is locked down at the network level. Only authorised personnel can reach DC VLAN 30, every login is authenticated through TACACS+, and all activity is logged via Syslog for audit purposes.
Insider Threat High Low Departments are isolated by VLAN. A compromised device cannot reach another segment without passing ACL inspection, and port security ensures only recognised devices can connect to switch ports.
WAN Link Failure High Medium EIGRP automatically reroutes traffic through the backup serial path using feasible successors. No manual intervention needed and no downtime for users.
Remote Worker Compromise High Medium Remote workers connect through a dedicated VPN interface on the Main ASA, keeping traffic separate from internal users. Each session has its own address pool and must pass through NAT before reaching anything inside the network.
10 — Validation
Live demo — physical build

Orlando branch skeleton network on physical Cisco enterprise hardware

Scope: The live demo used physical Cisco enterprise equipment to build the Orlando branch site as a proof-of-concept skeleton network. The remaining sites (Main, Chicago, Data Center) exist in the Packet Tracer simulation. Orlando was selected because it incorporates the core design elements: inter-VLAN routing, local DHCP, ACLs, ASA firewall, and EIGRP, sufficient to validate the full design on real hardware. The wireless segment was excluded from the physical demo as the available router only had two GigE ports, both required for the ASA uplink and switch trunk.
Physical Equipment Used

Cisco ISR Router (2x GigabitEthernet, 2x Serial) · Cisco Catalyst 48-port switch · Cisco ASA 5506-X. All enterprise-grade, consistent with project equipment recommendations.

Inter-VLAN Routing

Router-on-a-stick topology with GigE trunk carrying 5 VLANs via 802.1Q subinterfaces. VLAN segmentation verified across all Orlando VLANs (10–50) with end-to-end PC ping results confirmed.

Local DHCP & Connectivity

Local DHCP pools configured on the Orlando router serving all five VLANs. Interface status and routing table verified via show ip route and show interfaces.

ASA Firewall & EIGRP

ASA 5506-X confirmed peering with Orlando router via EIGRP. Perimeter security zone enforcement and NAT validated on physical hardware. ACLs tested restricting inter-VLAN traffic per security policy.

Security Controls

SSH v2 confirmed requiring credentials on the Orlando router. AAA/TACACS+ authentication verified. Port security with sticky MAC and violation restrict confirmed on the access switch. Unused switch ports shut down.
